# Learning Visuals

Create exactly one visual that exposes a relationship words cannot show as efficiently. A missing visual is cheaper than a decorative or misleading one.

## Decide whether a visual earns its place

Visualize:

- dependency graphs
- systems and flows
- sequences and state transitions
- trees and hierarchies
- side-by-side structural comparisons
- coordinates, vectors, plots, or physical layouts

Do not visualize a sentence merely by placing it in a box. Do not duplicate an equation that is already clearer on its own.

## Reduce before drawing

State the single idea the image must communicate. Remove every node, arrow, label, and decoration whose deletion preserves that idea. Prefer five elements to fifteen.

## Choose the representation

- Use an inline Mermaid block for nodes, edges, flows, sequences, states, and hierarchies.
- Use SVG only when exact position, scale, geometry, or custom shapes carry meaning.
- Use a normal plot generated by the active experiment when measured data is the lesson.

## Verify correctness

Check every label, direction, dependency, unit, ordering, and boundary against the lesson. For SVG or rendered output, inspect the actual visual with the browser or image-reading tool before presenting it. For Mermaid, keep syntax boring and labels short so Obsidian and terminal renderers agree.

## Present

Introduce the visual with one sentence. Let the image carry the relationship; do not narrate every element again in prose. Save generated assets inside the active subject directory, using unique descriptive filenames.
